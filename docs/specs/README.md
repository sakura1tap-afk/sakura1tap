# Specs

> 大一点的功能先在这里写规格，再进入代码实现。

使用规则：

- 一个功能一份 spec。
- 先写目标、边界、验收标准和风险。
- 状态从 `draft` 开始，确认后改为 `planned`。
- 实现完成后，在对应 spec 中记录验证结果，或者在 `CHANGELOG.md` 中引用该 spec。

命名建议：

```text
YYYY-MM-DD-short-feature-name.md
```

示例：

```text
2026-07-01-main-panel-keyboard-navigation.md
```

模板：

- `SPEC_TEMPLATE.md`
