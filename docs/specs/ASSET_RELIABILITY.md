# 静态资源可靠性维护

## 本轮结论

2026-09-07 线上复核时，正式路由、入口背景、首页两张场景图、四段实验室视频和排行榜均能加载。GitHub `main` 仍包含 532 个 `public/` 文件，约 112 MB；问题不是素材被统一删除。

旧 Worker 对不存在的静态文件沿用 SPA 回退，会返回 `index.html`。浏览器随后把 HTML 当成 JavaScript、图片、视频或模型解析，最终只表现为黑块、白屏或“打不开”，缺少可诊断信号。

## 维护策略

- 页面路由继续使用 SPA 回退。
- 带文件扩展名的请求若回退为 HTML，Worker 改为返回 404 和 `X-Content-Type-Options: nosniff`。
- `/api/health` 使用 `HEAD` 检查八项关键资源，不下载大文件正文。
- 资源探测覆盖入口背景、主要场景、代表视频、主 GLB 与 Live2D runtime。
- 动效实验室按窗口隔离视频错误，并允许原位重试。

## 验收标准

- `/api/health` 的 `database` 和 `assets.status` 均为 `ready`。
- `assets.failed` 为空，`assets.checked` 为 8。
- 不存在的文件返回 404，不返回 `text/html`。
- 单个视频加载失败时页面仍可操作，窗口显示“片段加载中断”，点击可重新加载。

## 后续边界

本轮不替换现有素材、不改首页视觉、不升级依赖。若特定地区仍出现批量超时，应继续检查 Cloudflare 区域链路与大文件首包，而不是重新上传已经存在的素材。
